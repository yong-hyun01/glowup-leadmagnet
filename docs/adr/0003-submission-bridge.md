# ADR 0003. 폼 제출 수집 방식: 브리지 스크립트 주입

- 상태: 채택
- 날짜: 2026-10-22

## 맥락
운영자 HTML 의 `<form>` 은 `action` 이 없거나 임의의 값을 가진다. 필드명도 운영자 마음대로다. 이 제출을 우리 DB 에 CRM 명단으로 저장해야 하고, 어느 채널로 들어온 방문자인지도 붙여야 한다.

## 고려한 대안
1. **운영자에게 `action="/public/api/..."` 를 직접 쓰게 하기.** 폼마다 URL 이 달라 AI 생성 HTML 을 그대로 쓸 수 없다.
2. **서버에서 HTML 파싱 후 `<form action>` 재작성.** JS 로 제출하는 폼엔 효과가 없다.
3. **서빙 시 브리지 스크립트 주입 (채택).**

## 결정
`/f/{slug}/frame` 응답 시 `</body>` 직전에 작은 스크립트를 주입한다. 스크립트는
- 문서의 **첫 번째 `<form>`** 의 `submit` 이벤트를 가로채고(`preventDefault`),
- `FormData` 로 모든 필드를 `{name: value}` 로 수집해(동일 이름은 배열),
- `POST {PUBLIC_BASE_URL}/public/api/forms/{slug}/submissions` 에 `{link_token, visitor_id, fields}` 를 보내며,
- 성공 시 폼을 숨기고 `success_message` 를, 실패 시 오류 메시지를 폼 아래에 표시한다.

설정값은 JSON 으로 직렬화하되 `<` 를 `\u003c` 로 이스케이프해 `</script>` 삽입으로 스크립트 컨텍스트가 깨지지 않게 한다. 브리지는 opaque origin 안에서 실행되므로 쿠키·관리자 API 에 접근할 수 없다 (ADR 0002).

## 결과
- 운영자는 AI 에게 "폼 하나 만들어줘" 만 요청하면 되고, 제출 연결은 시스템이 책임진다.
- 폼이 2개 이상이면 첫 번째만 수집된다. 과제 범위(단일 신청 폼)에서는 충분하다고 판단했다.
- 파일 업로드 필드는 무시한다(문자열만 저장). 범용 폼 빌더는 범위 밖이다.

# ADR 0007. 요구사항 해석과 가정

- 상태: 채택
- 날짜: 2026-10-22

과제 안내에 명시되지 않은 부분은 다음과 같이 가정하고 구현했습니다.

| # | 불분명한 점 | 가정 |
|---|---|---|
| 1 | "단일 .html 파일" 의 조건 | 확장자 `.html`, UTF-8, 512KB 이하, `<form>` 1개 이상으로 제한합니다. 외부 CSS/JS/폰트는 https 로만 로드를 허용합니다 |
| 2 | 캠페인과 폼의 관계 | 캠페인 1 : 폼 N 으로 봅니다. 폼은 HTML 템플릿 하나를 참조하며, 같은 템플릿을 여러 캠페인에서 재사용할 수 있습니다 |
| 3 | "커스텀 신청 폼" 의 커스텀 범위 | 이름·성공 메시지·활성 여부까지로 봅니다. HTML 자체 편집(범용 폼 빌더)은 범위 밖입니다 |
| 4 | 신청 데이터 스키마 | 운영자 HTML 의 필드명을 그대로 키로 하는 JSON 으로 저장합니다. 필수 필드 검증은 HTML 의 `required` 에 맡기고, 서버는 "빈 제출" 만 거부합니다 |
| 5 | 중복 신청 | 같은 사람이 여러 번 제출해도 모두 저장합니다. 중복 제거는 CRM 후속 처리로 봅니다 |
| 6 | 운영자 수 | 1명 이상의 운영자가 모든 데이터를 공유합니다. 운영자별 데이터 분리는 하지 않습니다 |
| 7 | 방문·방문자·전환율 정의 | ADR 0004 를 따릅니다 |
| 8 | 비활성 폼 | 공개 페이지·배포 링크·제출 API 모두 404 를 반환합니다. 기존 데이터는 유지합니다 |
| 9 | 삭제 | 캠페인 삭제 시 폼·링크·방문·신청을 함께 삭제합니다. 폼이 참조하는 템플릿은 삭제할 수 없습니다(409) |
| 10 | 시간대 | DB 는 UTC 로 저장하고, 관리자 화면은 KST 로 표시합니다 |
| 11 | 실행 환경 | 단일 서버·단일 도메인을 가정합니다. 공개 폼을 별도 도메인으로 분리하는 것은 `PUBLIC_BASE_URL` 로 가능하지만 기본값은 아닙니다 |
| 12 | 지원 채널 | 인스타그램·X·유튜브·스레드 4개로 고정합니다. 채널 추가는 enum 과 마이그레이션 변경이 필요합니다 (ADR 0006) |
| 13 | HTML 안에 폼이 여러 개인 경우 | 첫 번째 `<form>` 만 수집합니다 (ADR 0003) |
| 14 | 봇·비정상 트래픽 | 봇 필터링과 제출 속도 제한은 하지 않습니다. 과제 범위에서는 측정 왜곡을 감수합니다 |
| 15 | 운영자 계정 관리 | 가입·비밀번호 변경 API 없이 시드 스크립트로만 계정을 만듭니다 |
| 16 | 개인정보 보관 | 신청 데이터의 보관 기간과 삭제 요청 처리는 정의하지 않습니다. 실제 운영 시 별도 정책이 필요합니다 |

# ADR 0007. 요구사항 해석과 가정

- 상태: 채택
- 날짜: 2026-10-22

과제 안내에 명시되지 않아 다음과 같이 가정했다.

| # | 불분명한 점 | 가정 |
|---|---|---|
| 1 | "단일 .html 파일" 의 조건 | 확장자 `.html`, UTF-8, 512KB 이하, `<form>` 1개 이상. 외부 CSS/JS/폰트는 https 로만 로드 허용 |
| 2 | 캠페인과 폼의 관계 | 캠페인 1 : 폼 N. 폼은 HTML 템플릿 하나를 참조한다. 같은 템플릿을 여러 캠페인에서 재사용 가능 |
| 3 | "커스텀 신청 폼" 의 커스텀 범위 | 이름·성공 메시지·활성 여부. HTML 자체 편집(범용 폼 빌더)은 범위 밖 |
| 4 | 신청 데이터 스키마 | 운영자 HTML 의 필드명을 그대로 키로 하는 JSON. 필수 필드 검증은 HTML 의 `required` 에 맡기고, 서버는 "빈 제출" 만 거부 |
| 5 | 중복 신청 | 같은 사람이 여러 번 제출해도 모두 저장한다. 중복 제거는 CRM 후속 처리로 본다 |
| 6 | 운영자 수 | 1명 이상의 운영자가 모든 데이터를 공유한다. 운영자별 데이터 분리는 하지 않는다 |
| 7 | 방문·방문자·전환율 정의 | ADR 0004 |
| 8 | 비활성 폼 | 공개 페이지·배포 링크·제출 API 모두 404. 기존 데이터는 유지 |
| 9 | 삭제 | 캠페인 삭제 시 폼·링크·방문·신청을 함께 삭제. 폼이 참조하는 템플릿은 삭제 불가(409) |
| 10 | 시간대 | DB 는 UTC 저장, 관리자 화면은 KST 표시 |
| 11 | 실행 환경 | 단일 서버·단일 도메인. 공개 폼을 별도 도메인으로 분리하는 것은 `PUBLIC_BASE_URL` 로 가능하지만 기본값은 아니다 |

# ADR 0004. 방문·방문자·신청·전환율 정의

- 상태: 채택
- 날짜: 2026-10-22

## 맥락
과제는 "캠페인별 방문, 방문자, 신청, 전환율과 채널별 성과" 를 요구하지만 각 지표의 정의는 명시하지 않는다.

## 결정
| 지표 | 정의 | 집계 소스 |
|---|---|---|
| 방문 (visits) | 공개 폼 셸 `/f/{slug}` 가 로드된 횟수. 새로고침도 1회로 센다 | `visits` 행 수 |
| 방문자 (visitors) | 1년짜리 쿠키 `glowup_vid` 기준 고유 방문자 수 | `COUNT(DISTINCT visitor_id)` |
| 신청 (submissions) | 저장된 CRM 명단 수. 같은 방문자의 중복 제출도 각각 센다 | `leads` 행 수 |
| 전환율 | 신청 ÷ 방문자. 방문자가 0 이면 0 | 계산값, 0~1 소수 4자리 |

- 방문 기록은 셸 GET 시 **서버에서** 남긴다. 프레임 로드나 별도 비콘에 의존하지 않아 스크립트 차단 환경에서도 집계된다.
- 채널별 성과는 같은 지표를 `visits.channel` / `leads.channel` 로 group by 한 것이다. 배포 링크 없이 직접 들어온 경우 채널은 `direct`.
- 프레임 `/f/{slug}/frame` 은 방문으로 세지 않는다 (셸과 항상 1:1 로 로드됨).

## 고려했으나 미채택
- **봇·새로고침 중복 제거(세션 단위 방문).** 정의가 복잡해지고 과제 범위에서 검증이 어렵다. 필요하면 `visits` 에 이미 `visitor_id`·`created_at` 이 있으므로 집계 쿼리만 바꾸면 된다.
- **전환율 = 신청 ÷ 방문.** 같은 사람이 여러 번 새로고침하면 전환율이 과소평가되므로 방문자 기준을 택했다.

## 결과
- 쿠키를 지우거나 다른 브라우저로 오면 새 방문자로 센다. 정확한 사람 수가 아니라 브라우저 수에 가깝다는 점을 운영자가 알아야 한다.
